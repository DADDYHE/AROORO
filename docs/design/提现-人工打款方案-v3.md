## 0. 定位与关键变更

### 0.1 相对 v2 的评审结论（已确认）

| 项 | v2 方案 | v3 定稿 |
|---|---|---|
| 方案选择方式 | 全局开关 `system_config.payout_mode` | **每单审批时管理员显式二选一**（无全局运营开关） |
| 收款方式 | 用户预留 ≥1 账号即可 | **提现时必须选择收款方式**（微信/支付宝/银行卡），无则当场填写；渠道决定可用方案 |

| 人工打款本质 | 后台内完成 | **系统外打款 + 后台事后记录确认**（confirmManualTransfer 是记账/确权动作） |

| 完整收款信息 | 未定 | **列表只显示脱敏；完整账号仅 super_admin 专属接口查看 + operation-log 审计** |
| 全局开关 | `system_config.payout_mode` | 废弃；保留 `WECHAT_TRANSFER_AUTO_ENABLED` 作为**运维总闸**（=0 时后台禁用自动选项） |
| 红线 | transfer.js 一律不动 | transfer.js 已加固（见 §14）；红线改为**自动路径行为保持可回归、人工方案不依赖 transfer.js** |

### 0.2 红线

- 🚫 自动打款路径（`approveWithdrawal` 的 auto 分支、`retryTransfer`、`transfer.js` 调用链）行为**不再改动**，保证可回归；
- 🚫 人工方案不依赖 `transfer.js`（不调用微信转账接口）；
- ✅ 允许对 transfer.js 做**缺陷修复**（如私钥格式、签名、代理等运维级问题），但需单独评审，不与人工方案混在一起。

## 1. 架构总览

```
用户提交提现（必选收款方式：微信/支付宝/银行卡；无账号则当场填写）
        │ requestWithdrawal({ amount, walletType, payoutMethod })
        ▼
      [pending]
        │ 管理员审批（每单强制二选一）
        ├── 自动打款（仅 payoutMethod=wechat 可选；env 总闸关闭时禁用）
        │       ▼
        │    [processing] ──transfer.js──►(用户确认收款)──► [completed]
        │
        └── 人工打款（任意渠道；super_admin 弹窗查看完整收款信息）
                ▼
        [approved, mode=manual] ──管理员系统外打款──► confirmManualTransfer
                                                      （凭证 + 实际金额 + 差异警示）
                ▼
             [completed]

  approved 记录兼容两种去向：重新自动转账（wechat）/ 确认人工打款（任意渠道）
```

## 2. 收款方式（payoutMethod）与方案约束

| 用户所选收款方式 | 自动打款 | 人工打款 |
|---|---|---|
| `wechat`（微信号/手机号） | ✅（走 openid） | ✅（管理员手动转） |
| `alipay`（支付宝账号） | ❌ | ✅ |
| `bank`（银行卡） | ❌ | ✅ |

- 提现单 `withdrawals.method` 复用为**用户所选渠道**（现硬编码 `'wechat'` 改为写入所选值）；
- 自动打款仅微信渠道可用（微信转账对象是 openid）；支付宝/银行卡只能人工打款，后台对应禁用“自动”选项；
- 旧记录 `method='wechat'` 按微信渠道兼容。

## 3. 收款账号（payee）

### 3.1 存储

`users.payee`（完整信息，本人维护、本人可改）：

```json
{
  "payee": {
    "wechat": "微信号或绑定手机号",
    "alipay": "支付宝账号",
    "bank": { "bankName": "开户行", "cardNo": "卡号", "holder": "持卡人" }
  }
}
```

**格式校验（前端即时 + 后端权威复检，前端可被绕过）**：
- 银行卡 `cardNo`：Luhn 校验，`holder` 持卡人非空；
- 支付宝 `alipay`：邮箱格式或 11 位手机号；
- 微信 `wechat`：非空且长度合理（微信号/手机号）；
- 任意渠道至少填一项即可，允许全空（使用时再强制）。

### 3.2 展示与权限

- **后端投影即脱敏（安全硬要求）**：`getWithdrawalList` / `getMyWithdrawals` 的投影层**只返回脱敏字段，响应体零完整账号字段**——不依赖前端隐藏；
- 后台列表只展示**脱敏摘要**（`微信 138****5678` / `招行 尾号1234 张三`）；
- 提现单 `payeeSnapshot` 只存脱敏快照（审批时定格），不落完整账号；
- 完整账号：仅两个出口——**super_admin 专属** `getFullPayeeInfo(withdrawalId)`（审批选人工 / 确认已打款弹窗调用，每次查看写 `operation-log`）与本人 `getMyPayeeAccounts`；
- 日志/告警一律脱敏。

### 3.3 提现时校验

- `requestWithdrawal` 必填 `payoutMethod`，且所选渠道账号已存在；
- 无账号 → 前端在提现弹窗内引导填写（收款账号管理内嵌）后再提交；
- 后端二次校验，防止绕过前端。

## 4. 状态机（不变，mode 每单定格）

```
requestWithdrawal → [pending]
approveWithdrawal(auto, wechat)  → [processing] →(确认收款)→ [completed]
approveWithdrawal(manual)        → [approved, mode=manual] → confirmManualTransfer → [completed]
rejectWithdrawal                 → [rejected]

撤销/取消边界（v4 新增）：
  pending             → 用户可自助取消（frozen→balance，status→cancelled；原因必填 + operation-log）
  approved(manual)    → 仅 super_admin 可撤销（强确认“尚未打款”+ 原因必填 + operation-log；frozen→balance，status→cancelled）
  processing(auto)    → 撤销需微信侧确认未受理（接 cancelTransfer），本版不扩自动路径，另案处理

新增状态：cancelled（两端枚举/标签/UI 同步增加）

approved 记录（无论 auto 失败还是 manual 待打款）：
  - 重新自动转账：仅 method=wechat 且 env 总闸开启；
  - 确认人工打款：任意渠道，需 payee 存在。
```

互斥保障：auto 走 `processing→completed`，manual 走 `approved→completed`，两状态不重叠；确认用条件更新防并发；`completed` 幂等。

## 5. 接口设计（后端）

### 5.1 partnerService（本人 openid）

| action | 入参 | 说明 |
|---|---|---|
| `getMyWithdrawals` | `{ page, pageSize, walletType? }` | 本人提现记录列表（前端记录页使用，投影脱敏） |
| `getMyPayeeAccounts` | - | 返回本人 payee（完整，仅本人可见） |
| `updatePayeeAccounts` | `{ payee }` | 校验渠道格式后写入；允许全空（使用时再强制） |
| `requestWithdrawal` | `{ amount, walletType, payoutMethod }` | 新增 payoutMethod 必填 + 渠道账号存在性校验；资金事务保留 |
| `cancelWithdrawal` | `{ withdrawalId, reason }` | **本人入口**：仅限本人 `pending` 记录；frozen→balance、`status=cancelled`、原因必填、operation-log |

### 5.2 adminService

| action | 权限 | 入参 | 说明 |
|---|---|---|---|
| `approveWithdrawal` | super_admin | `{ withdrawalId, mode }` | 每单二选一；`mode='manual'` 走人工分支；缺省/`'auto'` 走现有自动分支（仅 wechat 可用，否则报错） |
| `confirmManualTransfer` | super_admin | `{ withdrawalId, payEvidence, payoutChannel?, paidAmount, manualNote? }` | 事后记录确认；幂等；差异警示+记录 |
| `getFullPayeeInfo` | super_admin | `{ withdrawalId }` | 返回完整收款信息 + operation-log |
| `getWithdrawalList` | **partner（普通管理员只读对账）** | - | 投影脱敏，补充 `mode/method/payeeSnapshot/payoutChannel/paidAmount/amountDiff/manualPaidBy/manualPaidAt/payEvidence/manualNote` |
| `getPayoutConfig` | partner | - | 返回 `{ autoTransferEnabled }`（读 env 总闸），供 web-admin 禁用 auto 选项 |
| `cancelWithdrawal` | **super_admin 入口** | `{ withdrawalId, reason }` | 撤销任意 `approved` 记录（manual 待打款或 auto 失败回退）：强确认“尚未打款”+ 原因必填 + operation-log；frozen→balance、`status=cancelled` |
| `retryTransfer` | super_admin | `{ withdrawalId }` | 原样保留（auto 重试/对账） |

### 5.3 confirmManualTransfer 规则

- `payEvidence` 必填（走现有 `uploadFile` 拿 fileID/URL，或流水号文本）；
- `paidAmount` 必填（实际打款金额），弹窗**预填 = 申请额**；
- `payoutChannel` 缺省取 `withdrawals.method`；
- 差异处理（策略 A + 容忍阈值）：`|差异| ≤ 0.01` → 仅记录 `amountDiff` 不炸屏；`|差异| > 0.01` → 红色强警示 + **必填差异原因**；结算一律按申请额，差额线下沟通；
- 打款对象一致性：确认弹窗同时展示「审批时 payeeSnapshot」与「当前 users.payee 脱敏」，不一致高亮提醒；确认后落 `paidToSnapshot`（本次实际打款对象脱敏快照）——防止用户在审批后改账号导致审计对不上；
- 前置（**mode 守卫，两道保险**）：① action 内先 `get` 读记录，校验 `mode==='manual'`，否则抛业务错误；② 条件更新 `where({_id, status:'approved', mode:'manual'})` 防并发。**不带 mode 守卫会把 auto 失败回退单（status=approved、无 mode）误判为人工已打款，甚至与 retryTransfer 并发双付**；`completed` 直接幂等返回；
- 落库：`completed + transferMethod:'manual' + payoutChannel + manualPaidBy/At + payEvidence + manualNote + paidAmount + amountDiff + paidToSnapshot`；
- 审计：`operation-log` + 失败 `recordAlert`。

### 5.4 共享落库

- 把 `settleWithdrawalCompleted` 参数化 `lockStatus`（⚠️ 工作区说明：该函数**当前分支**已抽到 `cloudfunctions/common/withdrawal-settle.js`（commit 753e0ca，wallet.js 仅 require）；**主仓库尚未合并该分支**，那里的实现仍在 `adminService/services/wallet.js:69` 本地——无论从哪个树实施，参数化的都是同一函数）：
  - auto：`lockStatus='processing'`（现有行为完全等价）；
  - manual：`lockStatus='approved'`；
- `confirmManualTransfer` 复用同一落库（事务 + 补偿双路径，幂等）。

### 5.5 审批分支（approveWithdrawal 顶部）

```js
// mode 由管理员显式传入，每单定格
if (mode === 'manual') {
  // 校验 payee 非空（快照脱敏写入 payeeSnapshot / method / mode='manual'）
  // 条件更新 pending→approved，防并发；不调 transfer.js
}
// 否则走现有 auto 分支（仅 method==='wechat' 允许，且 env 总闸未关）
```

## 6. 运维总闸

- `WECHAT_TRANSFER_AUTO_ENABLED`（env，默认开启）：`=0/false/off` 时后台禁用“自动打款”选项、`retryTransfer` 拒绝自动重试；
- 与每单选择叠加：总闸关闭 → 即使选微信渠道也只能人工；
- 总闸只影响审批动作，不影响存量记录状态。

## 7. 后台（web-admin）

- 审批对话框：展示用户收款方式 + 脱敏账号；**每单强制二选一**（自动仅微信渠道且总闸开启时可选）；选人工时提供“查看完整收款信息”（super_admin + 审计）；
- **权限分支（v5）**：普通管理员（partner）只读查看提现列表做对账——列表可见，通过/拒绝/确认/撤销/查看完整账号等按钮隐藏并提示“只读”；super_admin 全量操作；侧边栏“提现审核”菜单对普通管理员放开（只读模式）；
- **总闸透出**：页面初始化调 `getPayoutConfig`，`autoTransferEnabled=false` 时禁用“自动打款”选项（即使渠道为微信）；
- `approved` 记录操作：
  - `mode=manual` → 「确认已打款」弹窗（凭证必填 + 实际金额必填 + 差异强警示 + 原因）；
  - `mode=auto/缺省` → 「重新转账」保留；同时提供「确认人工打款」（payee 存在时）兼容 auto 失败遗留单；
  - 撤销入口（super_admin）：强确认文案“请确认尚未打款，否则会造成资金双失”+ 必填原因；
- `processing` → 保留「对账」按钮（auto 中途态）；
- `completed` → 展示打款方式（自动/人工）+ 申请/实际金额 + 差异 + 凭证链接；
- `api/withdrawal.js` 新增 `approveWithdrawal(mode)`、`confirmManualTransfer`、`getFullPayeeInfo`、`getPayoutConfig`、`cancelWithdrawal`。

## 10. 幂等 / 防重 / 安全

- 审批与确认均用条件更新占位（`status=pending` / `status=approved`），并发仅一个成功；
- `completed` 直接幂等返回；
- auto/manual 状态互斥，杜绝双付；
- 完整收款信息仅 super_admin + operation-log；日志/告警脱敏；
- 打款金额差异必录必示，防“打错钱瞎确认”。

---

## 11. 存量兼容

- 旧记录 `method='wechat'` → 视为微信渠道；
- 旧记录无 `mode` → 按 `auto` 处理（审批对话框对存量 pending 默认展示自动选项）；
- `payeeSnapshot` 缺失的 manual 记录 → 确认时实时取 `users.payee` 脱敏补写；
- 切换不影响存量记录，只影响后续审批动作。

## 15. 评审意见采纳记录（v4）

1. **后端投影即脱敏**（安全硬要求）：列表/详情接口响应体零完整账号，完整账号仅 `getFullPayeeInfo`（super_admin+审计）与本人 `getMyPayeeAccounts` 两个出口。
2. **payee 中途变更一致性**：`confirmManualTransfer` 落 `paidToSnapshot`（实际打款对象脱敏快照）；确认弹窗并列展示审批快照 vs 当前账号，不一致高亮。
3. **差异容忍阈值**：`|差|≤0.01` 仅记录；`>0.01` 强警示+必填原因；结算按申请额，差额线下沟通。
4. **撤销/取消边界**：`pending` 用户自助取消；`approved(manual)` 仅 super_admin 撤销（强确认尚未打款）；`processing(auto)` 另案；新增 `cancelled` 状态（枚举/标签/UI 两端同步）。
5. **收款账号格式校验**：前端即时（Luhn/支付宝格式/非空）+ 后端 `updatePayeeAccounts` 权威复检。
